## 1. 面向瑞芯微 RK3588 的嵌入式平台移植架构

### 1.1 技术协议移植要求与 RK3588 硬件资源约束

依据《技术协议书》第 7 条（“毫米波雷达数据处理整体算法并行化、轻量化加速技术”）与第 8 条（“面向嵌入式平台的算法移植技术：面向目前主流的人工智能芯片瑞芯微 RK3588，对上述技术研究形成的算法进行移植，完成功能性能验证”），“毫米波雷达点云处理及显示”系统完整移植并部署至两块 **瑞芯微 RK3588（8G RAM + 64G ROM）** 嵌入式计算板卡（RK3588 是基于 ARM64 架构的高性能八核异构 SoC 芯片，本部署平台受限于单板 8GB 运行内存 RAM 与 64GB 闪存存储 ROM），所有节点均在板载操作系统的 **Docker 容器**（轻量级操作系统级虚拟化容器环境）内运行。

针对嵌入式移植的核心工程约束：
1. **8GB 内存上限与 OOM（Out of Memory，内存耗尽崩溃）防护**：Open3D（开源现代三维数据处理库）内部几何容器采用双精度 `Eigen::Vector3d` 存储，需在队列深度、聚类上限、滑窗长度与累计覆盖网格四个维度建立全链路内存有界机制。
2. **64GB 存储空间保护**：部署配置默认关闭 `.ply`（Polygon File Format）中间结果落盘开关，避免长时间运行填满闪存。
3. **ARM64 容器图形显示与跨板大包传输**：开发板 1 与开发板 2 之间需跨以太网可靠传输单帧数兆字节的闭合白模网格 `O3DMesh`，同时开发板 2 容器需支持无重型桌面 GPU 驱动下的稳定渲染输出。

### 1.3 跨板 ROS 2 Foxy DDS 通信域与 QoS 官方规范部署

**ROS 2（Robot Operating System 2）Foxy Fitzroy** 底层采用 **DDS（Data Distribution Service，数据分发服务）** 作为去中心化通信中间件。在双板 RK3588 容器部署中，系统严格依据 **ROS 2 Foxy 官方文档**（`https://docs.ros.org/en/foxy/index.html`）的以下规范配置通信域与服务质量策略：

> **【ROS 2 Foxy 官方文档摘译 —— *The ROS_DOMAIN_ID* & *About Quality of Service settings*】**  
> 1. **逻辑通信域（`ROS_DOMAIN_ID`）**：DDS 使用域 ID 计算用于自动发现（Discovery）与用户通信的 UDP 端口号。同一物理局域网内，配置相同 `ROS_DOMAIN_ID` 的节点可自动发现并互通数据，不同 ID 的节点则逻辑完全隔离。默认域 ID 为 `0`，受 16 位无符号 UDP 端口计算限制，理论取值范围为 `0` 到 `232`；为防止与 Linux 操作系统临时端口区间（`32768–60999`）发生冲突，官方建议安全域 ID 选在 **`0` 到 `101`（含）** 之间。  
> 2. **服务质量策略（QoS）**：每个 QoS 配置由多项独立策略组合构成：  
>    * **历史记录（History）**：`Keep last` 仅缓存最新 $N$ 条样本（由队列深度 `Depth` 配置）；`Keep all` 缓存所有样本直至达到中间件资源上限；  
>    * **可靠性（Reliability）**：`Reliable` 保证样本送达接收端，在丢包或分片缺失时可多次重传；`Best effort` 尽力投递，网络不佳时允许丢包；  
>    * **持久性（Durability）**：`Volatile` 不持久化历史样本；`Transient local` 要求发布者持久化缓存样本供“后加入”订阅者接收。  
>    * **兼容性规则**：遵循“提供（Offered）vs. 请求（Requested）”匹配原则，发布端策略必须等于或高于订阅端请求，否则将发生静默不匹配，可通过 `ros2 topic info <topic> --verbose` 核查两端 QoS 一致性。

据此，本项目在两块 RK3588 容器内配置一致的安全 `ROS_DOMAIN_ID`，并在 `gmz_node`、`ransac_node`、`parallel_dbscan_node`、`flow_alignment_node` 与 `connection_test` 中统一部署 `rclcpp::QoS(rclcpp::KeepLast(5)).reliable().durability_volatile()`：以 `KeepLast(5)` 锁定内存队列深度，以 `reliable()` 确保大包跨板分片可靠重组，以 `durability_volatile()` 避免历史大包常驻缓存；同时确保 `reconstruction` 的 `message_filters::Subscriber` 与上游发布端 QoS 策略严格匹配。

## 3. 整体算法并行化与轻量化加速技术（协议条款 7 专项落实）

为满足技术协议“在算法性能相当的情况下大幅提升运行速度”的轻量化与并行化加速要求，系统对全链路 9 个功能包实施了多层次协同加速：

### 3.1 编译级加速与紧凑扁平接口序列化 (`ament_cmake` / `pc_msgs`)

1. **ARM64 `-O3` 编译优化**：全部 C++ 功能包在 `CMakeLists.txt` 中均开启 `-O3` 与 `-std=c++17`，充分释放 RK3588 多核指令流水与 NEON 向量化加速能力。
2. **扁平化单精度接口 (`pc_msgs`)**：基于 ROSIDL（`rosidl_default_generators`）生成的 `O3DPointCloud`、`ClusteredPointCloud` 与 `O3DMesh` 直接采用连续一维 `float32[]`/`int32[]` 数组传输，相较通用 `PointCloud2` 与双精度传输大幅削减 CPU 反序列化开销与板间网络流量。

### 3.2 输入层零磁盘 I/O 预加载与内存预分配 (`io_handlers`)

`sim_lidar_data_flow_node` 与 `sim_plane_data_flow_node` 在启动期调用 `open3d::io::CreatePointCloudFromFile` 一次性预加载并展平全部 `.ply` 数据，预先 `vector::reserve(num_points * 3)` 避免动态内存重分配拷贝，运行期彻底消除磁盘 I/O 延迟。

### 3.3 $O(N)$ 哈希滤波、稀疏地面抽样与多线程 DBSCAN (`ground_segmentation` / `clustering`)

1. **$O(N)$ 64 位联合哈希与稀疏地形抽样 (`gmz_node`)**：将 2D 网格坐标打包为 `uint64_t` 哈希键，两遍线性扫描完成异常抑制、坡面拟合与地形分类；每网格仅输出 1 个稀疏代表点供泊松重建，将下游输入点数压缩 1~2 个数量级。
2. **并行 DBSCAN 与巨团拦截 (`parallel_dbscan_node`)**：调用 Open3D 内部多线程并行 `ClusterDBSCAN` 加速密度聚类；通过 `cluster_max_samples`（3000）与 `max_cluster_extent`（500.0 m）拦截超大连通簇，防止下游建图算力尖峰。

### 3.4 泊松深度轻量化、$128 \times 128$ 空间索引与局部执行器隔离 (`reconstruction`)

1. **泊松八叉树深度轻量化与分位数裁面**：依据 **Open3D 官方文档** *Poisson surface reconstruction* 说明摘译：
   > **【Open3D 官方文档摘译 —— *Poisson Surface Reconstruction*】**  
   > 泊松曲面重建通过求解带正则化项的优化问题，从带定向法向的点云中生成平滑表面。其中 `depth` 参数定义了重建内部八叉树（Octree）的剖分深度，直接决定了最终三角网格的空间分辨率；`depth` 越高，网格细节越丰富，但计算耗时与三角面数呈指数级上升。同时函数返回顶点密度估值 `densities`，推荐结合分位数阈值调用 `RemoveVerticesByMask` 裁除点云缺失处外推产生的低密度伪影面片。
   部署配置将 `poisson_depth` 轻量化固化为 `6`，并结合 `density_quantile: 0.06` 裁剪冗余低密度三角面，大幅降低 RK3588 CPU 耗时与跨板 `O3DMesh` 传输体积。
2. **$128 \times 128$ 空间索引 (`TerrainHeightGrid`)**：将全地形高程查询从暴力 $O(F)$ 遍历加速至常数级 $O(1)$ 单元格内检索，高效支撑地下杂点过滤、OBB 防穿模抬升与铁塔依托高程估计。
3. **铁塔 CAD 预加载预旋与局部执行器**：启动期一次性完成高压铁塔网格加载与旋转矩阵预乘；依据 ROS 2 Foxy *Executors* 官方规范，为铁塔查询服务客户端独立实例化局部 `rclcpp::executors::SingleThreadedExecutor`，通过 `spin_until_future_complete` 安全隔离服务等待，避免单线程主执行器自旋阻塞。

### 3.5 滑窗定长体素降采样与多尺度早停收敛 (`flow_alignment`)

1. **滑窗限长与 Open3D `VoxelDownSample`**：依据 **Open3D 官方文档** *Voxel downsampling* 说明摘译：
   > **【Open3D 官方文档摘译 —— *Voxel Downsampling*】**  
   > `voxel_down_sample` 使用规则三维体素网格从输入点云创建均匀下采样的输出点云，常作为各类点云处理与配准任务的前置降维加速步骤。算法分两步执行：（1）将输入点按空间坐标分桶落入对应的体素单元中；（2）对每个被占用的体素单元内的全部点坐标（及颜色、法线）求均值，生成一个唯一代表点，从而显著降低点密度并抑制局部噪声。
   限定滑动窗口 `window_size: 4` 并施加 `VoxelDownSample(3.0)`，锁定配准参考地图点数、计算耗时与内存上限。
2. **多尺度早停收敛**：ICP 在单步平移 $< 10^{-4}\text{ m}$ 且旋转 $< 10^{-3\circ}$ 时立即提前终止迭代，并支持关闭可选调试点云发布（`pub_map_pc_topic: ""`）。

### 3.6 5 米网格累计去重、`std::async` 三层并发软光栅与光流尺度缩放 (`visualization`)

1. **5 米空间网格累计去重 (`Coverage`)**：在 `offline_terrain_display` 模式下剔除重复覆盖区域的冗余三角面，防止多帧叠加导致渲染面数与内存线性膨胀。
2. **多线程并发软光栅与光流降采样**：利用 C++17 `std::async` 将历史累计层、前一帧更新层与当前帧更新层的 CPU 软光栅渲染并发调度至 RK3588 多核执行，并直接推送至原生 X11 窗口 `NativeFrameWindow`；在 DIS 光流插帧模式下采用 `interpolation_flow_scale: 0.25` 将光流像素计算量压缩至 $1/16$。

### 3.7 进程组隔离、管道日志分流与零 DDS 开销监控 (`bringup`)

双板配置均置空 `efficiency_monitor_topic: ""`，由 `bringup_node` 从子进程标准输出管道直接解析 `[STAGE-DONE]` 信号统计 **FPS（每秒帧率）** 与阶段瓶颈，零额外 DDS 传输与反序列化损耗；同时通过 `setpgid(0, 0)` 独立进程组与 `SIGINT`/`SIGKILL` 超时强杀杜绝僵尸进程残留。
